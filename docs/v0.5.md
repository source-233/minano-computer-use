# 0.5：事实反馈、数据保真与观察控制

状态：0.5.0 已实施并通过仓库验证及限定范围复核，尚未全局安装、提交或推送。
最终证据与未验证范围见 [verification.md](verification.md)。
第二轮代码复核确认的反馈与图片坐标绑定问题均已修复并回归；当前最终全套
为1112项通过。后台窗口smoke因桌面鼠标移动而安全中止，不记作通过；详细证据
与边界见verification.md，原1036项记录仅为修正前基线。

目标不是让工具推断“远程拦截”或“游戏已接受输入”，而是使 agent 能从有界、
无损、可追溯的事实反馈中自行判断下一步。保持原有七个工具及三种输入通道。

## 1. 本版交付范围

| 优先级 | 能力 | 解决的问题 | 不作出的承诺 |
| --- | --- | --- | --- |
| P0 | UIA 失败原因可区分 | 不再把异常、RuntimeId/PID/HWND/祖先检查失败统称为“控件离开 root” | 不放宽校验，不自动重搜/重放动作，不宣称已修复 Edge 现场根因 |
| P0 | 64 位身份时间无损输出 | JS 客户端接收和回传时不丢失 process_creation_time 低位 | 不用时间容差，不归因于历史进程真的重启 |
| P0 | 原生动作投递回执 | 明确实际目标、事件方法、down/up 提交、耗时与 cleanup，而非只返回 invoked | 不把事件接受数量等同于游戏消费数量 |
| P1 | 紧凑的输入上下文反馈 | 让 agent 看到前台、目标线程布局、可得 IME/修饰键状态与未知项 | 不自动切输入法、不自动纠正用户键态，不输出远程拦截结论 |
| P1 | 运行实例与版本信息 | 区分当前常驻进程、磁盘包和仓库 HEAD | 未嵌入的 revision/build 标识不猜测，不把当前文件 hash 当成内存证据 |

上述 P0/P1 均已实施。IME open/conversion 和未嵌入的 build/revision 明确为
unknown/null，而非伪造完整诊断；未增加设备、驱动、厂商适配器或诊断平台。

## 2. UIA 拒绝反馈：说明检查失败，不替 agent 下因果结论

保留 `refused` / `STALE_TARGET` 的拒绝语义，附加小型结构化证据，例如：

```json
{
  "code":"STALE_TARGET",
  "message":"UIA membership could not be established",
  "details":{
    "stage":"focus_before_read",
    "node_index":12,
    "predicate":"ancestry_unavailable",
    "error_type":"COMError"
  }
}
```

上述形状为本轮实现契约。诊断须区分“确认不匹配”和“无法读取”，
不能把未知当作 false 的业务事实。只保留首个决定性失败和必要的有界证据，
不罗列全树或完整祖先链，不包含名称、值、选区和 provider 异常原文。
必须在原校验点捕获证据，不能事后重新查询或重新映射，再把新的观察冒充本次
失败的原因；已无法知道的原始值就保持 unknown。

已失效元素的内容仍丢弃；安全拒绝、token 失效、write uncertainty、截图分量
独立成功和 non_atomic 契约不变。详细原因被预算裁剪时，至少保留拒绝 code 和
有限 predicate，不能为了容纳诊断丢掉动作失败/不确定性。

## 3. 大整数输出：在对外边界统一无损表示

- `process_creation_time` 对外统一为十进制字符串或 null。不能继续提供一个
  可能已舍入的同义 number 字段让调用者误用。
- Python 内部的 Win32、worker IPC、绑定比较、token 与坐标上下文仍使用精确
  整数；转换不进入内部决策。不是改写所有数值，也不改变 HWND/PID 的意义。
- 文本 JSON 与 `structuredContent` 使用同一份已转换结果，并在转换后计算
  输出预算。state、动作回执、截图、进程等公开结果保持一致，包括嵌套 binding。
- trace 若复用该公开结果则采用相同表示，并说明记录格式；不修改已经存在的
  历史 trace，也不把 Python 私有中间值误当 MCP schema。
- 这是 0.5 的明确输出类型变更，需更新示例/迁移说明。客户端如自行构造身份
  比较，使用字符串精确比较，不能先转 JS Number。现有工具不新增手填绑定入口。

## 4. 原生动作反馈：投递回执与业务观察分层

每个原生动作沿用现有 result/时间/cleanup，在键盘路径补充紧凑回执：

- **target**：本次实际解析的 HWND/PID；进程创建时间可得时附加，未知时明确。
  使用已解析目标，不为回执重新按标题搜索，也不因辅助信息不可得偷偷切目标。
- **delivery**：实际使用的 SendInput 或既有消息方法，而不是只回显请求参数。
  键动作区分请求解析出的 VK 与实际结构的 wVk/scan/flags；SCANCODE 下实际
  wVk 为零，不能用请求 VK 代替实际 wVk。数据来自发送对象，不事后重新映射。
  text/paste 不回显内容、字符序列或剪贴板。
- **counts**：请求事件数、系统确认接受数、未确认/失败及阶段。只有底层返回
  才记 accepted；异常或中断时记 unknown，不能写成零或全成功。
- **lifecycle**：down/up 的提交结果、requested duration 和测得的投递间隔。
  测得时间不是游戏持键时间，API 接受 up 也不是游戏已松键的证明。
- **cleanup**：保留原有所有者线程松键规则与最终结果，区分动作正常 up 和
  finally 清理，不重复计数、不为追求完整回执额外重放 down/up。

按 chord/阶段聚合，不为长输入返回逐字符事件日志。compact 预算下保留首个
失败、部分接受、未确认释放和 may_have_acted 等关键事实。辅助观察失败只嵌套
报告，不得将已经生效的动作改成 refused，或将成功改写为“游戏无响应”。
先裁剪辅助上下文而非关键动作证据；真实投递失败不能降格为 warning。
取消与所有者线程松键优先，不等待可选反馈完成才开始清理。

`invoked` / `consumption_verified=false` 不变：false 表示未确认消费，不是
已经证明未消费。`act` 的批次完成计数仍表示执行/投递流程，不表示任务完成。

## 5. 输入上下文：小型快照，不是一套自动诊断系统

默认动作回执紧凑；需要较详细输入上下文时，在 act/play 使用反馈级别
`feedback="compact"|"detailed"`（默认 compact）。该开关只控制
元数据，不替代或混淆现有 `screenshot=false|true|"text"|"auto"`。

有界、只读的可得信息：

- 前台 HWND/PID 与本次目标是否匹配；可读时提供目标线程的 focus HWND。
- 目标线程 HKL、语言标识，以及 ImmIsIME 等实际调用结果。
- IME open/conversion 状态仅在目标上下文、调用边界和超时都有可靠保障时提供；
  否则 unknown。不采集组词文字/候选词，不把 ImmIsIME=true 写成“正在中文组词”。
- Shift/Ctrl/Alt/Win 当前按下状态，明确为带时间的观测，不能解释历史状态或
  当作该工具持有的键。只释放本工具持有的输入。
- 若包含会话事实，严格限定为 MCP/目标 Session ID 与已验证的 Windows 会话
  类型。RDP=false 不代表没有 ToDesk，也不代表不存在拦截。

不得为辅助反馈引入无超时的跨进程 SendMessage、COM/IME 查询或新的长调用锁。
遇到读取失败、预算不足、目标变化或取消，返回有界未知/观察错误；不改变动作
既有后置状态和释放优先级。上下文与截图均为非原子观察，必须有时间/范围。

不默认扫描远控进程、网络连接、厂商私有日志或设置；不添加
`remote_intercepted=true/false` 等没有足够证据支撑的判断。agent 可以据回执
提出环境检查，工具不代替 agent 发试验按键或执行实验。

## 6. 运行身份与截图控制

### 6.1 system(status)

补充包版本、运行实例 ID、进程/启动信息及可验证构建标识（可选）。这些信息
在进程启动时确立，不能在每次调用时读取仓库 HEAD 假装是运行 revision。
worker 重启不混同 server 重启。只有真实嵌入的标识才能宣称对应构建；未知
revision/build 明确标注。默认不输出完整本机路径、用户名等无关数据。

### 6.2 window(state)

加入现有截图工具已有的 `capture_mode` / `allow_fallback` 选择，沿用已有
后端名字、权限、timeout、目标 binding 与错误语义；默认仍是 screen、禁止
未经授权的 fallback。禁止为了取图激活窗口。PrintWindow 失败可独立报告，
不把 UIA 已得到的有效分量一起丢弃；root binding 真失效时仍丢弃两个分量。

UIA 与图像仍非同帧，默认图片仍 JPEG800/quality75。反馈失败不自动重做动作，
PrintWindow 图像也不自动获得物理坐标点击保证。WGC 本机故障不会在本版被
顺带宣称修复或通过默认 fallback 掩盖。

## 7. 明确不包含

- 自动诊断/修复 IME 或远程屏蔽、自动输入实验、自动切窗/切语言。
- ToDesk 专用适配器、全局阻断探测、BlockInput 试探、输入 hook/驱动/虚拟 HID。
- 新的 Raw Input/游戏输入后端，或以更高权限绕过目标输入规则。
- 放宽 UIA/token/坐标唯一性、取消/松键规则、shell/process-control 权限。
- 将未复现的 Edge 状态问题、FH6 C/W 问题标成“已解决”。
- 自动安装全局 wheel、commit/push。实现、安装、实机测试分别取得所需授权。

## 8. 实施分工与依赖

先冻结输出 schema 与预算/脱敏规则，再拆互不重叠的写入范围：

跨模块约定：native execute 增加关键字 feedback（默认 compact），仍返回原有
result，顶层附 `target_binding`、`receipt`；detailed 时另附 `input_context`。
receipt 将请求的 VK 与实际事件字段分开，未知的接受数量/目标创建时间不伪造。
runtime 只向支持该参数的注入测试后端传递 feedback，不因 TypeError 重放动作。
UIA 拒绝诊断放入 `error.details`；外部时间戳转换在 server/trace 公共结果边界
执行，不进入 worker、runtime 绑定或 capture 坐标决策。

原生侧实现口径：receipt 的事件计数来自实际尝试的调用；短返回只保留确认的
接受前缀，其余记录 unknown，异常不伪造已拒绝。正常 up 归动作回执；异常
finally 的释放记录归独立 cleanup 回执。详细上下文仅在该动作正常释放或
清理后采集；取消或仍持有输入时跳过，避免延迟批次最终释放。它不是按键
按住期间的实时状态快照。`dispatch_interval_seconds` 从首个到最后一个实际
投递调用起点测量，只有一次调用时为 null，不是游戏持键时长。

协议层已冻结的补充：system.status 的新增字段为 `package_version`、
`instance_id`、`pid`、`started_at`（Unix 秒）、`build` 与 `revision`。
未嵌入构建元数据时后两者为 null；instance_id 在 Runtime 初始化生成，不随
UIA worker 的生命周期改变。新增 trace 采用 schema 2，标记
`identity_time_format="decimal_string_or_null"`；仅保留聚合回执与静态失败原因，
不记录事件明细或输入上下文。旧 trace 不改写。

1. **UIA lane**：失败原因与有界诊断，仅 UIA 模块和针对性测试。
2. **native lane**：投递回执、只读输入上下文、清理忠实性，native/独立辅助模块
   与针对性测试；不处理工具 schema。
3. **runtime/protocol lane**：外部数字转换、版本身份、反馈参数与 state 截图
   透传。它独占 runtime/server/output/contracts 等共享文件，不与其它 lane
   同时写这些文件。
4. **parent**：schema 契约、版本/文档、三条 lane 的整合和最终验收。

每 lane 只跑本范围测试；合并并冻结后，再做一次最终全套。发现具体失败后
定向修复/复测，不把每次进度更新当成再次全套测试的理由。

## 9. 验证路径与验收边界

| 声明 | 验证所有者 | 最小证据 | 不能替代的证据 |
| --- | --- | --- | --- |
| 拒绝原因真实、无敏感数据泄漏 | UIA lane | 对每个失败 predicate 和 provider 异常的 fake 回归，验证拒绝不变、原因有界及无明文；同树安全节点正常路径 | 不能宣称真实 Edge 导航根因已定位 |
| JS 客户端可无损读取身份时间 | protocol lane + parent | Python 内部/IPC 精确性；真实 MCP text/structuredContent 类型一致；JS parse/stringify 往返 `134387468188212291` 与 null/嵌套 binding/预算裁剪测试 | 只在 Python assert 大整数相等不够 |
| 投递回执符合实际底层调用 | native lane | fake adapter 验证接受数量、部分发送、异常未知、取消、焦点丢失、down/up、cleanup、不重放和密码/text 脱敏 | 不证明游戏消费事件 |
| 输入上下文读取诚实且不改环境 | native lane | fake 不支持/失败/不一致/超时测试；证明无切换 IME、无全局松键、无主动输入；详细反馈失败保留主结果 | 当前 HKL 不证明历史组词，未知不能写 false |
| 运行身份是本进程事实 | protocol lane | 版本/实例在同进程稳定、不同实例不同；未知 build 不填仓库 revision；无完整本机路径 | 磁盘 wheel hash 不证明历史进程所加载的代码 |
| state 后端选择和独立分量语义不退化 | protocol lane | 假后端参数透传/超时/partial/identity 回归；自有窗口实际 PrintWindow 读图验证 | 不证明任意游戏无遮挡像素或同帧 |

最终仓库门禁：`uv run --no-sync ruff check .`、
`uv run --no-sync ruff format --check .`、`uv run --no-sync pytest -q`、
stdio schema/回执 smoke、自有 UIA/截图 fixture、既有 PyAV 回归及 `uv build`。
有运行中的 MCP 时使用 --no-sync，避免可执行文件锁导致环境同步失败。

真实原生输入/IME 对照不是默认单测。若另获授权，只在自有 fixture 里进行有界
输入观测；用户游戏、切语言或远控连接对照需要额外授权并遵守既有停止边界。
若本版只有合成输入证据，交付明确写“反馈功能已验证，FH6 根因仍未确认”。
