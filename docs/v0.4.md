# 0.4: background messages and application state

User-approved scope: three concrete gaps relative to open-computer-use 1.1.4:
background window messages, combined application state, rich element discovery.
Seven public tool names remain. Implementation and deployment were verified
before the user separately authorized the 0.4 release commit and normal push.

## Input selection

`act` and `play` add `input_mode=None|'uia'|'native'|'message'`.
Omitted mode preserves the current `native` boolean. Explicit native/message mode
is the single-call opt-in: do NOT require another launch flag or native=true.
Reject native=true with explicit uia/message to avoid conflicting selectors;
native=false is the existing default, not an explicit denial. No item may override
mode, no automatic routing/fallback between channels. Report delivery='message'.
`key_method` remains for the existing foreground-native route; message mode
rejects nondefault key_method to avoid hidden meaning. Force-focus, look, paste,
shell, arbitrary messages are NOT background actions. Caller selects target.

### BackgroundInput (A)

`BackgroundInput(adapter=None)`; `.set_cancel_event(event|None)`;
`.execute(action,target,timeout=5.0)->dict`; `.release_all()->dict`; `.close()`.
Production uses a disposable spawned worker with isolated stdio for all blocking
Win32 reads/sends; whole-call cancellation/deadline via existing UIABroker pattern
allowed, no COM objects cross. A may use existing UIABroker(worker_target=...) with
a fixed message worker only. Fake adapter runs in-process for unit tests only.

`normalize_message_action(action:dict)->dict` pure function validates all fields,
using existing native normalizer for compatible fields AFTER stripping envelope.
Runtime calls it for the entire plan before any effects. Canonical allowed:
key/hold/key_down/key_up/text/set_value/move/click/mouse_down/mouse_up/drag/wheel.
Existing aliases accepted when valid. set_value requires value:str; text uses
WM_CHAR (UTF16 code units); set_value uses WM_SETTEXT plus bounded WM_GETTEXT
readback only on standard Edit/RichEdit, not generic UIA. No EM_REPLACESEL pointer
payload without a separately proved marshaling contract. No clipboard mutation.
Reject NUL text/set_value, invalid Unicode and unsupported actions up front.
Optional action `recipient` is explicit integer HWND or `hwnd:...`; root itself
or a descendant in SAME PID only. Root target resolved uniquely and bound to
HWND/PID/process-creation time, all required for writes. Recipient resolved fresh
and checked before each send; no title-based rediscovery after binding.

For key/text without recipient, choose the focused child reported for the target
GUI thread ONLY if it is in this bound root; otherwise the root itself (not global
foreground, not a desktop-wide search). Report chosen recipient. Mouse actions
default use recursive ChildWindowFromPointEx within bound root (same-PID check,
bounded32 levels); explicit recipient allowed but coordinate must be contained.
`x/y` are physical screen coordinates (or Runtime maps proven image coordinates
first). Convert to recipient client coordinates under scoped physical DPI context;
mouse lParam signed16, reject overflow/no clamp. Wheel uses screen-coordinate
lParam and correct axis/sign; button flags and X buttons explicit. Move dispatches
WM_MOUSEMOVE without SetCursorPos. Double/triple are bounded sequences, normal
down/up timing; drag total duration and cancellation held-state cleanup.

No foreground requirement. No SetForegroundWindow/SetFocus/AttachThreadInput/
SendInput/SetCursorPos calls anywhere in this route. No UIA fallback. Target
application can still activate itself; report before/after foreground/cursor.
All payloads use bounded synchronous SendMessageTimeoutW, including key, mouse
and WM_CHAR: do not mix posted text with sent WM_SETTEXT and thereby reorder our
operations. A WM_NULL send or sleep is not a queue-consumption barrier. Dispatch
failure => error/unknown depending prior dispatch. Successful message
submission is invoked/consumption_verified=false; set_value may be verified ONLY
with exact bounded native readback. SendMessageTimeoutW uses timeout, worker hard
deadline still covers hung crossprocess provider. WM_* codes are fixed, no public
arbitrary wParam/lParam. Scoped cleanup releases only message states owned by this
backend to SAME bound recipients. Hard worker kill after a possible down => cleanup
unconfirmed and may_have_acted, never fake verified release or start a new worker
just to say old holds were released. A helper may expose BATCH capability later,
but current API must remain callable by C with native-like execute/release_all.

### UIA state and rich metadata (B)

`rich:bool=False` accepted on tree/text/find/inspect; `state` defaults rich=True.
Existing core metadata/selector uniqueness/token validity unchanged. Safe optional
fields: class_name, localized_control_type, native_window_handle, enabled,
offscreen, has_keyboard_focus, focusable, is_password, frame, value, actions.
Each optional provider failure is per-field `unavailable` evidence, never false
values/default-success. Bound strings4096, listcounts, output budgets existing.
`actions` from advertised/retrievable Pattern support only, NEVER invokes patterns;
supported verbs already implemented invoke/set_value/toggle/select/expand/collapse/
scroll_into_view/scroll. Read-only ValuePattern must not advertise set_value.
BoundingRectangle frame explicitly labels provider_screen coordinates. Only mark
physical if proved DPI context; never enable automatic physical fallback by geometry.

Password redaction applies to ALL text/value reads including inspect/tree/text/
find/state and mutation readback reports; no raw entered value in results or trace.
Aggregate ancestor ValuePattern values also obey descendant unsafe/unknown scope;
text_redacted must never coexist with a leaked aggregate value. Omitted nodes after
worker/server output budgeting invalidate their focus/selection references and
associated payload, never silently point the index at another element.
If IsPassword capability unavailable, do not claim password safety; rich may expose
unknown flag and conservative omit values. Preserve fixtures that lack optional
properties by marking unavailable rather than breaking existing basic traversal.

UIABackend action='state': requires explicit target, reuses scoped root and one
traversal. Result data={nodes,truncated,focus,selection,window,...}. focus scoped to
targetroot via RuntimeId/path/native descendant validation; OS foreground HWND is
separate observations, never imply global focus belongs to requested app. Focus
discovery can use traversed HasKeyboardFocus or GetFocusedControl checkedancestry;
if uncertain report unavailable, no out-of-root details. selection is bounded
TextPattern.GetSelection ranges from proven same-root focused element (or explicit
selector), <=16ranges and total4096chars; read without selecting or focusing.
Password/unknownpassword => no plaintextselection. Include componenttimes and
rootbinding, no atomic snapshot claim. `include_ax=False` handled C avoid worker.
Traversal membership is not a continuing ancestry guarantee: revalidate live root/
candidate RuntimeIds and bounded ancestry before/after focus, selection and rich
reads, and discard plaintext on reparenting or native-HWND/root mismatch.

### Runtime and seven schemas (C)

`window(action='state',target,...include_screenshot=True,include_ax=True,
rich=True,text_limit=500, max_dim=800,format='jpeg',quality=75, depth/max_nodes,
timeout/max_output budgets)` returns independent image top-level frame and JSON
data={uia, screenshot, interval, consistency:'non_atomic', component_errors}.
UIA componentdata holds B nodes/focus/selection/window. Resolve exact root binding
BEFORE either component; call both against same hwnd and verify PID/create after.
Capture original binding remains exact; reject stale instead of captionretarget.
UIA failure still allow read-only screenshot, screenshotfailure still retainUIA;
overall partial for componentfailure, error/refused if no success. include_ax or
include_screenshot false genuinely omits work; bothfalse refuse. screenshot context
same caller_scope handling as existing. Componenttimes monotonic; no sameframeclaim.
Rootbinding unavailable => refuse to compose trustedstate, don'tinventtimestamp.

`act/play` select mode once beforevalidation; message is separate BackgroundInput
instance (injectable `message=None`), per-action timeout forwarded (boundedremaining),
release_all ownerfinally. message supports UIA-style set_value but must use message
normalizer not UIA path; `native` default remains unchanged. No automatic forcefocus.
message auto-feedback gives full boundstate: UIA+image when available, using state
helper SAMEoperation (no nestedcontroller deadlock), auto onlyUIAtext nativeimage
kept as-is. Observation failure does not overwrite primary action status/uncertainty.
Every message feedback variant (auto, true image, text) must use the original
action's exact HWND/PID/process-creation binding. A title reused by another window
cannot supply feedback. Missing or changed binding yields an observation error,
never caption rediscovery; text/OCR cannot bypass that binding requirement.
Rich fields/selectedtext never defaulttrace. Generic cancellation stays independent
of longcall lock/defaultexecutor. Status advertises available_input_modes.
play script can route compatible commands to message; unsupported look/paste/focus
wholeplan rejects beforeeffects. Existingnative keywords stillfrontendcompatible.
